## Remarques (aucune ne bloque ; issues à ouvrir par l'auteur)

1. Garde `isHandlingAnnotationTap` inutile (préexistant). Tous les MAPTAP du journal montrent
   `handling=false` : le drapeau est levé après le toucher carte. Il peut seulement avaler un
   toucher carte qui suit dans les 0,2 s. Le correctif ne dépend plus de lui, mais le code le
   laisse croire. À simplifier ou à commenter.
2. Le correctif suppose que `nil` puis la nouvelle boîte arrivent dans la même mise à jour. Si un
   futur iOS sépare ces deux étapes, la fiche se fermerait puis se rouvrirait. Elle aurait les
   bonnes détentes (contre-épreuve E1 de l'auteur), donc ce serait un saut, pas le symptôme.
3. Titre « Boîte #14 183 » : l'`Int` est formaté avec séparateur de milliers
   (`BookBoxSheet.swift:68`). Cosmétique, préexistant (visible sur toutes les planches).
4. En changeant de boîte, la place photo montre la roue environ 0,2 s, même pour une photo déjà
   vue (`apres-1…`, capture `04-vers-14183-01-t0175ms`). C'est l'effet attendu de `.id(box.id)`.
   La hauteur ne bouge pas. Cosmétique.
5. Glisser vers le haut : une image de transition à 0,24 s montre la fiche qui se ferme pendant
   que le détail arrive (`apres-5-glisser-vers-haut-rafale.png`). Rien ne reste à l'écran. Ce
   chemin de code n'a pas changé.
6. CHANGELOG ligne 38 : l'exemple « v1.3.0 (11) » date du build 11. À mettre à jour ou à rendre
   générique.
7. Outillage de l'auteur (`captures-M0019/outillage/project.yml`) : il pointe vers le worktree
   `F03-M0019` et le build 10. Il n'est pas rejouable tel quel. J'ai dû exclure `Info.plist` des
   sources (`Multiple commands produce …/Info.plist`). Mon outillage rejouable est dans
   `captures-R015/outillage/`.
8. Mesure : ma sonde lit les détentes UIKit avant que SwiftUI les applique au changement 320 ↔
   200. Elle affiche donc la valeur précédente sur ce cas. L'écran fait foi (`apres-3-…`).
   Ce n'est pas un défaut de l'app.
9. Non testé : échec réseau de `photo_url` (place réservée), et l'iPhone réel. Le symptôme
   d'origine a été vu sur iPhone. Un contrôle sur l'appareil après installation du build 12 est
   conseillé, sans bloquer.
